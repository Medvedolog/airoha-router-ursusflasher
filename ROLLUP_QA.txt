Primary safety fixes in TEST61:
- IDENTITY1: one TEST61 identity across .scmversion, URSUS_VERSION, native version, Web/API and build metadata.
- NOAUTOFIP1: ONE-CLICK never self-updates an already installed UrsusBoot automatically. Existing UrsusBoot updates are explicit operator actions only.
- UBIATTACH2: explicit FIP self-update reuses an already attached expected ursus-ubi-full; no unconditional ubi detach -> ubi part cycle. Attachment mismatch stops before writer.
- UPLOADRETRY1 / UPLOADABORT2: 75 s reconnect grace; a new full transfer cycle starts only after operator y/N; failure before operation POST records transaction_state=NOT_STARTED.
- SESSIONRECOVERY1: upload/validation/precheck failures before writer do not lock WebFailsafe into a dead session; another attempt remains possible.
- Direct stock mtd0 write always has one y/N after backup/preflight. EXPERT item 1 may explicitly skip the full stock backup for the current test run; the required live mtd0 capture remains.
- POSTSYSRESET1: after successful UBI update with keep_settings=1, UrsusFlasher offers an optional OpenWrt settings reset.
- DIAGSTATE1: stock self-update no longer reports a false UBI_VERIFY success stage.
- EMERGENCYMETA1: production TEST61 FIP hash metadata and emergency BootROM alpha3 hash metadata are separate; changing the production target cannot invalidate the emergency payload validator.
- REPROZIP1: PUBLIC TEST ZIP uses fixed SOURCE_DATE_EPOCH ZIP metadata and must rebuild byte-for-byte.
- ROUTE1 integration: a positive nokia_stock fingerprint reaches the authenticated read-only stock probe; generic HTTP remains ambiguous.
- Checkout/package integration: root launchers resolve both source and exported layouts; UI terms resolve config/UI_TERMS.json; manifests include TEST61 and use OS-independent path ordering.
- CONFIGTRIM1 remains inherited from TEST60: UBIFS/PXE/extlinux command families stay removed while UBI/TFTP/WGET and bootcmd=ursusdispatch remain.

Revoked lines:
- TEST59 and TEST60 are REVOKED_FOR_HW_USE because split identity could trigger a redundant destructive FIP write and their UBI self-update attachment path is not accepted for new hardware tests.
