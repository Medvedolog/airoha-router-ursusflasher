# Правки к пресетам NAND в живой консоли

Патч для `dev/ursusboot-t75-nand-presets` — этой ветки нет в моём рабочем
дереве, поэтому изменение лежит здесь, а не коммитом.

## База и применение

Собран поверх `a58351247e87a5eabeaea8e2ba51f5146048c59c`
(`fix: use physical MTD children only and hide unverified MF stock partition aliases`).

```sh
git checkout dev/ursusboot-t75-nand-presets
git am patches/nand-presets-hardening/0001-fix-keep-nand-presets-working-past-t75.patch
```

## Что внутри

Четыре правки в `ursusflasher/src/ursus_ws_nand.py`, плюс расширенный
`selftest_ws_console.py` и раздел в `docs/NAND_WS_PRESETS_RU.md`.

| # | Что было | Что стало |
|---|---|---|
| 1 | `version.endswith('-t75')` | флаг `tftpput_available`, иначе сравнение поколения `-tNN` с 75 |
| 2 | порт 1069 зашит с обеих сторон | порт выбирается один раз на вход в меню, 1069 предпочитается, занятый — заменяется, все сообщения называют фактический |
| 3 | `ubi detach` по устаревшему снимку статуса | безусловный терпимый detach через уже открытую консольную сессию |
| 4 | одна общая фраза на семь причин отказа | поле, которое разошлось, + отдельное объяснение изменившейся карты плохих блоков |

### 1. Пин версии

Был точным сравнением: на t76 пресеты выключились бы молча. Теперь решает
возможность, а не номер. Если прошивка начнёт публиковать
`tftpput_available` в `/api/status`, вывод по номеру перестанет
использоваться автоматически — **это стоит добавить на стороне UrsusBoot**,
чтобы хост перестал угадывать.

### 2. Порт

Занятый 1069 раньше заканчивал операцию. Теперь выбирается свободный, но
1069 сохраняет приоритет, чтобы правило в firewall оставалось предсказуемым.
Отказ TFTP GET дополнительно подсказывает про firewall — на практике это
самая частая причина.

Компромисс назван прямо: запасной порт менее удобен для заранее
настроенного firewall, поэтому он выбирается только когда 1069 действительно
занят, и программа его называет.

### 3. `ubi detach`

Первая версия этой правки перечитывала статус по HTTP. Её видно в истории
рассуждений, но в патче её нет: она добавляла вторую транспортную
зависимость прямо перед деструктивной фазой, что хуже той несвежести,
которую лечила. Итоговый вариант ничего не спрашивает — detach при
отсутствии присоединённого UBI является no-op, поэтому проверка «а надо
ли» только добавляла способ ошибиться. Настоящий отказ detach проявится на
первом `mtd erase`, где он однозначен.

### 4. Сообщения об отказе

Маркеры `URSUS_NAND_ARCHIVE_FOREIGN field=…` и
`URSUS_NAND_BADBLOCK_MAP_CHANGED` сделаны по той же схеме, что уже
используется в проекте (`URSUS_STOCKSLOT_REFUSED reason=…`,
`URSUS_MAC_SOURCE=RI`): стабильная машинная часть плюс локализованное
объяснение. Иначе QA зависела бы от `NOKIA_LANG`.

## Проверено

```text
python3 ursusflasher/tools/selftest_ws_console.py          PASS
NOKIA_LANG=en  то же самое                                  PASS
python3 ursusflasher/tools/selftest_item4_direct_ubi.py     PASS
python3 ursusflasher/tools/selftest_network_faults.py       PASS
python3 ursusflasher/tools/selftest_restore_routes.py       PASS
py_compile ursusflasher/src/*.py + scripts/*.py             PASS
```

Это полный шаг «Host contract QA» из `md-item4-direct-ubi.yml`. Аппаратного
подтверждения нет и не заявляется: ни один из путей F5 на железе в рамках
этой правки не прогонялся.

Новые проверки в `selftest_ws_console.py`:

- `nand_generation_contract` — t74 отказ, t75/t76/t100 допуск, явный флаг
  перекрывает номер в обе стороны;
- `nand_transfer_port_contract` — свободный 1069 предпочитается, занятый
  приводит к запасному порту (тест устойчив к машине, где 1069 уже занят);
- в `nand_restore_contract` — `ubi detach` обязан произойти до первого
  `mtd erase`.
