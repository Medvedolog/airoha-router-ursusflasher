# UrsusFlasher 0.2.56 — эксплуатационная инструкция

Эта инструкция относится к Nokia XG-040G-MD на Airoha AN7581.

## 0. Обязательно: сброс Nokia на заводские настройки

**Перед каждой итерацией роутер должен быть сброшен на заводские настройки.** Это касается и первой установки, и любого повтора после неудачной попытки.

Сброс выполняется **на стоковой прошивке Nokia**: нажать кнопку Reset и удерживать её **не менее 20 секунд**, затем отпустить и дождаться полной перезагрузки.

Без сброса состояние стоковой системы непредсказуемо: остаются изменённые настройки, включённые или отключённые службы и следы предыдущих попыток. Определение устройства и штатный доступ в этом случае могут повести себя не так, как ожидает UrsusFlasher.

## 1. Подключение

Для прошивки рекомендуется использовать **LAN2 или LAN3**.

- LAN1 работает через отдельный PHY Airoha EN8811H и не используется как основной порт для переходов между прошивками.
- LAN4 после загрузки комплектной OpenWrt-сборки назначается WAN, поэтому доступ к `192.168.1.1` через него может пропасть.
- Для аварийного восстановления через BootROM требуется USB-UART 3,3 В. Подключаются TX, RX и GND. VCC не подключается.

## 2. ONE-CLICK

**ONE-CLICK всегда устанавливает OpenWrt с разметкой UBI.** В комплекте есть два образа — для разметки UBI и для заводской, — но автоматический сценарий во всех своих ветках использует только UBI и выбора не предлагает.

Если нужна **заводская разметка**, это делается вручную одним из двух способов:

- **EXPERT, пункт 3 «Записать пользовательскую прошивку OpenWrt»** — укажите комплектный `fw/openwrt-airoha-an7581-nokia_xg-040g-md-squashfs-sysupgrade.bin`. Пункт принимает любой `.bin`/`.itb`, класс образа определяется сам, запись пойдёт по заводскому пути.
- **Веб-интерфейс UrsusBoot** — загрузите тот же файл в Recovery и нажмите «Установить в заводскую разметку».

Переход односторонний: заводскую разметку можно поставить с заводской Nokia, но не с уже установленной OpenWrt UBI — такой образ отклоняется до записи.

### Windows

```text
START_ONECLICK.cmd
```

### Linux / macOS

```bash
./START_ONECLICK.sh
```

ONE-CLICK сначала определяет текущее состояние роутера.

### Заводская Nokia STOCK

Используются:

1. HTTP/Web — определение заводской системы и получение штатных данных доступа.
2. Telnet — root-сеанс для чтения состояния и работы с MTD.
3. TFTP — передача полной резервной копии на ПК и подготовленного `mtd0` обратно на роутер.
4. UrsusBoot Recovery — запись OpenWrt после установки загрузчика.

Перед первой записью NAND создаётся и проверяется полная копия `mtd0..mtd16`.

### Уже установленная OpenWrt

Используются root SSH и SCP.

UrsusFlasher различает:

```text
PERSISTENT_ROOT  — OpenWrt исполняется из постоянной flash-памяти
RAM_ROOT         — OpenWrt/initramfs исполняется из оперативной памяти
```

Если существует UBI-том `fip`, обновляется он. Физический boot block используется только при однозначно подтверждённой цели и подходящем содержимом текущего загрузочного блока.

### UrsusBoot Recovery уже запущен

Используется HTTP API на `192.168.1.1`.

Образы передаются по частям через HTTP, проверяются загрузчиком и только затем допускаются к записи.

## 3. EXPERT

Запуск:

```text
START_EXPERT.cmd
```

или:

```bash
./START_EXPERT.sh
```

Меню:

```text
── УСТАНОВИТЬ ───────────────────────────────────────
 !  1  Установить OpenWrt
       резервная копия → UrsusBoot → комплектная OpenWrt; транспорт выбирается автоматически
 !  2  Установить или обновить UrsusBoot
       OpenWrt: SSH; Nokia STOCK: Web/Telnet; UrsusBoot Recovery: HTTP/TFTP
 !  3  Записать пользовательскую прошивку OpenWrt
       OpenWrt: SSH → sysupgrade -T → sysupgrade; Recovery: HTTP

── ЕСЛИ РОУТЕР НЕ ЗАГРУЖАЕТСЯ ──────────────────────
 !  5  Восстановить загрузчик
       USB-UART → Airoha BootROM → UrsusBoot из RAM → запись и проверка
 !  6  Восстановить заводскую прошивку Nokia
       из проверенной резервной копии; пока не реализовано

── РЕЗЕРВНЫЕ КОПИИ ──────────────────────────────────
    7  Создать полную копию flash-памяти
       BootROM/USB-UART → RAM → чтение NAND → копия на ПК
    8  Проверить резервную копию
       локально на ПК: структура, размеры и SHA256
    9  Собрать комплект восстановления
       из проверенной резервной копии; пока не реализовано

── ПОСМОТРЕТЬ ───────────────────────────────────────
   10  Состояние устройства и доступные операции
       пассивная диагностика Web/SSH
   11  Flash-память, разметка и сбойные блоки
       Web/SSH, при необходимости USB-UART; только чтение
   12  Проверить файлы комплекта
       локальная проверка SHA256 и состава файлов
```

`!` означает, что операция может выполнять запись во flash-память (NAND).

Пункт 4 объединён с пунктом 2 и скрыт из меню; старый ввод `4` выполняет пункт 2. Пункты 6 и 9 пока недоступны.

## 4. Установка или обновление UrsusBoot

Пункт 2 автоматически выбирает рабочий транспорт:

```text
Nokia STOCK
  -> Telnet из запущенной заводской прошивки Nokia

OpenWrt + PERSISTENT_ROOT
  -> SSH из установленной OpenWrt

OpenWrt + RAM_ROOT
  -> SSH из OpenWrt, запущенной из оперативной памяти
```

Перед записью показываются определённое состояние устройства и выбранный способ выполнения операции.

## 5. Пользовательская прошивка OpenWrt

Пункт 3 выбирает способ по текущей среде.

- Из установленной OpenWrt: root SSH → передача образа в `/tmp` → `sysupgrade -T` → одно подтверждение → `sysupgrade -v -n`. Опция `-F` не используется, настройки предыдущей сборки не переносятся.
- Из UrsusBoot Recovery: образ передаётся через HTTP API, проверяется Recovery и только затем допускается к записи.

## 6. Полная резервная копия

Пункт 7 выполняется без записи в NAND.

### Nokia STOCK

Если безопасный путь чтения доступен, сохраняются `mtd0..mtd16`, метаданные устройства и контрольные суммы. Дополнительные службы не включаются только ради резервного копирования.

### OpenWrt и BootROM / RAM

Если фоновая диагностика видит OpenWrt и SSH, но не может подтвердить `root` без пароля, после выбора пункта 7 системный OpenSSH запросит пароль `root`. UrsusFlasher его не сохраняет и не устанавливает временный ключ на роутер.

Для точной копии OpenWrt UBI используется Airoha BootROM → XMODEM → проверенная recovery-среда в RAM → read-only чтение `/dev/mtd0` → TFTP на ПК. Сохраняется полный физический образ 256 МиБ `mtd0_all_flash.bin.gz` и его SHA256; для UBI дополнительно формируются `mtd1_bl2.bin.gz` и `mtd2_ubi.bin.gz`. NAND не записывается.

## 7. Проверка резервной копии

Пункт 8 автоматически различает заводскую резервную копию и точный raw BootROM-backup. Для raw-копии проверяются `RAW_BACKUP.json`, полный 256-МиБ `mtd0_all_flash.bin.gz`, SHA256 всех файлов и, при UBI-разметке, размеры производных `mtd1_bl2`/`mtd2_ubi`. Для заводской копии сохраняется прежняя проверка полного набора `mtd0..mtd16`.

## 8. Аварийное восстановление через USB-UART

Пункт 5 используется при отсутствии рабочего сетевого входа.

Последовательность начинается с запуска служебного U-Boot из RAM через Airoha BootROM. Передача preloader и RAM-компонентов выполняется по XMODEM.

Перед любой постоянной записью снимаются сведения о текущих UBI/FIP/BL2. Если безопасная цель записи не определена, восстановление прекращается без изменения flash-памяти.

Подробности: `docs/EMERGENCY_URSUSBOOT_RU.md`.

## 9. Проверки до записи

Перед разрешением записи UrsusFlasher проверяет применимые к текущему пути сведения:

- модель и SoC;
- текущую систему и разметку;
- загрузчик;
- root-доступ;
- среду выполнения OpenWrt;
- целевой MTD-раздел или UBI-том;
- размер и SHA256 файлов;
- состояние резервной копии, если она обязательна для операции.

Если обязательные сведения не получены, write-capable действия блокируются.

## 10. Проверки после записи

Для загрузочных объектов используется полное обратное чтение и сравнение с ожидаемым содержимым или SHA256.

При несовпадении автоматический повтор другим способом не выполняется.

## 11. Проверка комплекта

## 12. Режим UrsusBoot Recovery

Обычный вход в Recovery после перезагрузки:

1. Дождаться общего мигания/перезапуска индикаторов.
2. Сразу зажать Reset.
3. Держать до последовательности: 2 коротких + 3 длинных красных мигания.
4. После постоянного красного света отпустить Reset.
5. Открыть `http://192.168.1.1`.

Если Reset зажат до подачи питания, используется Airoha BootROM, а не обычный UrsusBoot Recovery.

## 13. Веб-интерфейс UrsusBoot: что появляется, что исчезает и что запрещено

Страница не показывает всё сразу. Она перестраивается по состоянию, которое загрузчик сообщает о роутере и о загруженном файле. Если элемента не видно — это не сбой, а условие, которое сейчас не выполнено.

### Что появляется и когда

| Элемент | Виден, когда |
|---|---|
| Панель хода операции | операция запущена |
| **Перезагрузить в OpenWrt / с новым UrsusBoot** | операция завершилась успешно |
| **Установить в заводскую разметку** | загрузчик сообщил, что установка в неё возможна |
| **Установить/обновить UBI** | загрузчик сообщил, что обновление UBI возможно |
| Галочка **«Сохранить настройки OpenWrt»** | роутер **уже** в разметке UBI **и** загружен UBI-образ |
| Кнопка **«Сбросить настройки OpenWrt»** | текущая разметка уже `OPENWRT_UBI` или `OPENWRT_STOCK_LAYOUT`, и никакая операция не идёт |
| Блок перехода в UBI | вы в контексте миграции |
| Строка причины загрузки | причина не «обычное включение» |

Два случая, которые чаще всего принимают за пропажу:

- **Галочки «Сохранить настройки» нет при первой установке.** Она и не должна появляться: при переходе с заводской Nokia или из заводской разметки сохранять нечего, и флаг принудительно выставляется в «не сохранять». Галочка — для обновления UBI поверх уже установленной UBI-системы.
- **Кнопки «Сбросить настройки» нет сразу после установки.** Она для роутера, на котором OpenWrt уже стоит и опознана. Пока вы в Recovery после установки, разметка ещё не переопределена.

### Что бывает неактивно

| Кнопка | Активна, когда |
|---|---|
| **Мигрировать в UBI** | пройдены все предварительные проверки перехода |
| **Обновить UrsusBoot** | FIP признан корректным и нет активной, завершённой или сорванной операции |
| Одноразовая загрузка образа | загруженный образ признан пригодным |

### Что загрузчик запрещает

Даже при видимой кнопке запись начинается не всегда. Отказ приходит с классом причины:

```text
OPERATION_LOCKED     нет проверенного образа нужного класса; идёт другая операция;
                     не пройдена предварительная проверка; нет подтверждения
LAYOUT_UNSUPPORTED   текущая разметка не поддерживает эту операцию
WRITE_FAILED         запись или сброс не завершились
```

### Вкладка «Консоль U-Boot»

Это настоящая командная строка U-Boot, а не набор заранее разрешённых кнопок: белого списка команд нет и блокировки операций записи на неё не распространяются. Всё описанное выше охраняет кнопки интерфейса, а не то, что вы наберёте здесь руками. По UART доступен тот же промпт.

Сборка основана на U-Boot v2026.07 с патчами OpenWrt/Airoha, поэтому команды работы с MTD, UBI/UBIFS, сетью и environment ведут себя как в обычном U-Boot.

Каждое разрушительное действие дополнительно требует точного подтверждения от страницы — `INSTALL-UBI`, `INSTALL-OPENWRT-STOCK-LAYOUT`, `UPDATE-URSUSBOOT`, `RESET-OPENWRT-SETTINGS`, `REBOOT`. Запрос без него отклоняется.

### Известное поведение

Кнопка перезагрузки отвечает `REBOOTING`, но фактический сброс выполняется после закрытия соединения. Если браузер удерживает соединение, роутер может остаться включённым — в этом случае перезагрузите питанием вручную. В UART-логе успешный путь помечается строкой `URSUS_UBI_MIGRATION_OPERATOR_REBOOT`.
