# Пресеты NAND в экспертной консоли UrsusFlasher

В сборке с UrsusBoot T75 откройте экспертную консоль WebSocket и нажмите **F5**
(на терминале без F-клавиш: **Ctrl+]**, затем **N**).

Подменю предлагает:

1. Снять всю основную область NAND.
2. Снять выбранный раздел из текущего списка MTD. Для MD со stock-разметкой
   дополнительно доступны разделы из подтверждённой диагностической карты.
3. Залить раздел из ранее созданного этим меню архива.
4. Залить весь NAND из ранее созданного этим меню архива.

Перед работой подключите ПК кабелем к роутеру с UrsusBoot WebFailsafe. ПК должен
достигать адреса UrsusBoot (обычно 192.168.1.1), а его firewall должен принимать
UDP на порту 1069. Отключите VPN и другие интерфейсы, если они перехватывают
маршрут. Консоль и команды идут по WebSocket/TCP; данные переносятся TFTP/UDP.

Архив — пара `.bin` и `.bin.json`. Файл содержит ECC-исправленную основную
область страниц по физическим смещениям. Плохие блоки обозначены байтами FF;
их список, геометрия, модель, ID NAND и SHA256 находятся в JSON. **OOB, OTP и
реальное содержимое плохих блоков не входят.** Это архив для восстановления
основных данных на совместимой геометрии, а не побитовая криминалистическая
копия чипа.

При заливке проверяются размер и SHA256 архива, плата, чип, геометрия, текущая
разметка и карта плохих блоков. Затем показывается сводка и запрашивается один
`y/N`. UBI отсоединяется перед записью. Программа пишет хорошие стираемые блоки,
сверяет карту плохих блоков до и после записи и проверяет каждый блок чтением и
SHA256. При полном восстановлении начальная область с загрузчиком идёт последней.
После ошибки дальнейшая запись останавливается; уже записанные блоки не
откатываются.

Не выбирайте произвольный `.bin` без соответствующего JSON. Если карта плохих
блоков изменилась или архив сделан на другом типе платы/чипа, это подменю
останавливается. Для восстановления чужого дампа с переносом серийника, MAC и
разметки нужен отдельный контролируемый сценарий; этот пресет не правит RI.

Проверено сборкой и host-тестами. Выполнение полного цикла на реальном MD/MF
остаётся аппаратным тестом.
