# Аварийное восстановление UrsusBoot через USB-UART / Airoha BootROM

Эта процедура используется, когда роутер не загружается и штатный сетевой доступ недоступен.

## Что требуется

- USB-UART адаптер **3,3 В**;
- подключение **TX / RX / GND**;
- **VCC не подключать**;
- ПК с UrsusFlasher 0.2.80-dev / UrsusBoot T80;
- доступ к кнопке Reset и питанию роутера.

## Запуск

Откройте EXPERT и выберите:

```text
5  Восстановить загрузчик
```

UrsusFlasher предложит выбрать UART-порт и проверит, что он не занят другой программой.

## Вход в Airoha BootROM

Для BootROM Reset удерживается **до подачи питания**:

1. Выключите питание Nokia.
2. Зажмите Reset.
3. Подтвердите готовность в UrsusFlasher.
4. Включите питание, продолжая удерживать Reset.
5. UrsusFlasher дождётся приглашения BootROM на передачу по XMODEM.

Это отличается от обычного UrsusBoot Recovery, где Reset зажимается уже после начала перезагрузки.

## Что загружается в RAM

UrsusFlasher передаёт по XMODEM:

```text
preloader
  -> RAM installer FIP
  -> служебный UrsusBoot в оперативной памяти
```

Аварийная BootROM-цепочка **прибита к проверенной alpha3 lineage**: exact alpha3 preloader / RAM installer / recovery FIP / BL2. Production T80 в эту RAM bootstrap-цепочку автоматически не подмешивается. Это отдельная compatibility boundary. Аварийная alpha3 lineage сохранена без изменения; production T80 имеет статус HW_PENDING и проверяется отдельно.

На этом этапе постоянная flash-память не изменяется.

## Какая версия будет записана — и свой FIP

Комплектный production target этой dev-итерации — **UrsusBoot `0.1.0-alpha5-t80`**; это не меняет проверенную alpha3 RAM bootstrap-цепочку.

Через BootROM в RAM всегда стартует **alpha3** (RAM installer) — это только загрузчик-помощник. В постоянную память пишется то, что вы выберете **до** входа в BootROM:

```text
1. UrsusBoot 0.1.0-alpha3 — проверенный аварийный образ + парный BL2   (Enter, по умолчанию)
2. Комплектный релиз UrsusBoot (если есть в комплекте)
3. Свой FIP-файл (на свой страх и риск)
```

Для каждого варианта показываются версия (она читается из самого FIP: распаковывается BL33 и берётся строка `UrsusBoot <версия>`), размер и SHA256; известные сборки подписываются по имени. Перед записью выводится блок **ЧТО БУДЕТ ЗАПИСАНО**.

- **По умолчанию (Enter)** поведение прежнее: alpha3 FIP + alpha3 BL2, ничего лишнего не спрашивается.
- **Варианты 2 и 3** пишут выбранный FIP тем же способом (том `fip` = static ID 4, запись, чтение обратно, побайтовое сравнение). **BL2 при этом по умолчанию не переписывается**; парный alpha3 BL2 можно записать, ответив `y` на отдельный вопрос.
- **Свой файл** принимается, только если это структурно корректный Airoha FIP: сигнатура и TOC, NT_FW на месте, влезает в окно boot-area, BL33 распаковывается, хеш не в чёрном списке проекта. Затем нужно набрать `CUSTOM FIP`. Файл, изменившийся после выбора, к записи не допускается.
- UrsusFlasher **не может проверить**, что выбранный FIP работает с BL2, который стоит в вашем роутере. Несовместимая пара может оставить роутер без загрузки; тогда снова нужен UART и BootROM. Именно поэтому по умолчанию остаётся alpha3, а комплектный релиз как аварийный образ на железе не проверялся.

Тот же блок «версия/размер/SHA256» показывается и в обычном обновлении UrsusBoot (Web, TFTP, UART): есть выбор «комплектный релиз» (Enter) или «свой FIP» с тем же `CUSTOM FIP`. Для пункта «восстановить boot-area из backup» показывается, какой FIP лежит внутри выбранного образа. Для MF-кандидата, собранного из вашего mtd0, показывается его версия; там тоже можно выбрать свой файл.

## Проверка перед восстановлением

После запуска U-Boot из RAM UrsusFlasher сначала выполняет чтение текущего состояния:

- список UBI-томов;
- фактические `fip*` тома и их ID;
- целевой раздел BL2;
- содержимое и контрольные признаки загрузочной цепочки.

Результаты сохраняются в:

```text
results/ursus-bootchain-state-*.txt
results/ursus-bootstrap-uart-*.log
```

Если безопасные цели записи не определены однозначно, восстановление прекращается **до записи**.

## Защитная проверка UBI ID 4

Аварийный механизм содержит проверку исторического UBI-контракта. Если ID 4 занят посторонним томом, например `bosa`, UrsusFlasher блокирует старую фиксированную операцию до изменения flash-памяти.

Это штатное защитное поведение: обнаруженная разметка не подгоняется под ожидаемую.

## Передача аварийных компонентов

После read-only проверки, если запись разрешена, точные аварийные **alpha3** FIP и BL2 передаются по XMODEM в RAM. Production FIP TEST61 и emergency alpha3 используют раздельные manifest/hash поля и не должны взаимно подменять друг друга.

Постоянная запись начинается только после отдельного подтверждения оператора.

## Проверка после записи

Записанный FIP и BL2 считываются обратно. Результат должен совпасть с эталонными данными аварийного комплекта.

При расхождении UrsusFlasher не выполняет автоматическую повторную запись другим способом.

## Обычный UrsusBoot Recovery после восстановления

Для обычного Recovery Reset **не держат до включения питания**.

При программной перезагрузке:

1. дождитесь общего мигания/перезапуска индикаторов;
2. сразу зажмите Reset;
3. держите до последовательности **2 коротких + 3 длинных** красных мигания;
4. после постоянного красного света отпустите Reset;
5. откройте `http://192.168.1.1`.

Если момент пропущен:

1. выключите питание;
2. включите питание;
3. примерно через 1 секунду зажмите Reset на 5–10 секунд;
4. дождитесь той же красной последовательности и постоянного красного света.

## После возврата загрузчика

Если после восстановления требуется установить текущий production-кандидат UrsusBoot `0.1.0-alpha5-UBIUX1-TEST61`, используйте EXPERT пункт 2 или явное действие WebFailsafe через уже доступную систему/Recovery. Аварийный BootROM alpha3-путь и штатная установка TEST61 — разные операции и разные lineage.
